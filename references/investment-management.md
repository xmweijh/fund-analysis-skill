# 基金投资与持续管理

这份流程用于指导真实研究与管理工作。投资方案由用户目标和约束推导，基础分只作辅助；不能先选一个高分基金，再反推用户应该承担的风险。

## 按任务取最少必要信息

- 用户只问一只基金、费用或产品差异：直接完成公开研究，不强迫先填完整个人问卷。
- 用户问“买什么、买多少、要不要调仓”：先使用已经确认的资料，只补当前最关键的3～5项缺口。缺少的信息可给区间、不披露或未知；继续完成不依赖它的公开研究。
- 用户已有持仓：先核记录日期、金额口径和代码/份额；不把一张截图当成完整家庭资产。

通常需要确认：资金用途与币种、首次/持续可投入金额、预计使用时间与刚性取用需求、应急/专项资金是否已划开、可以承受的损失金额与承受期限。说明风险意愿和经济承受能力的区别。“能接受跌15%”还须明确是单只基金、基金账户还是全部投资资产，以及是否包括备用现金。

不需要账户号、证件、密码或精确薪资。不要凭年龄、职业、基金数量或平台风险标签自动设定组合比例。未确认目标比例时，可以比较配置方案及条件，不生成个人精确目标金额。

## 先资金安排，再配置，再选产品

1. 把应急、专项和长期投资用途分开；产品是否合适先看取用时间、损失承受和实际赎回条件，不只看历史回报。
2. 讨论资产类别、地区、行业、币种和策略的作用，形成用户可选择的目标范围。方案要说明主要风险、机会成本和需要放弃什么，不能承诺损失上限。
3. 用户确认目标后，在同一角色中比较可实际购买的产品。优先减少同标的、同主题或相同经理风格的无效重复；更多基金不等于更分散。
4. 再讨论一次投入、分期投入、定投或先保留现金的条件。定投分散入场时间，不保证赚钱，也不能消除标的持续下跌、主题集中和资金期限不匹配。

没有全市场筛选结果时，把研究对象称为“已核验候选”，不声称最优、全市场第一或已完成全量筛选。提出替代产品前核对最新身份、合同、渠道可买状态、费用、规模与流动性；不把旧推荐器的排序直接交给用户。

## 产品研究与候选比较

共同信息：准确代码/份额、管理人、合同类别与风险特征、业绩区间、同类口径、经理任期、规模与持有人集中、配置披露日、完整费用、申赎规则及资料来源。只展示实际取得且与本次决策有关的项目。

| 产品 | 必须回答的决策问题 |
| --- | --- |
| 货币/现金管理 | 普通与快速赎回各适用什么渠道/额度？到账能否匹配用途？不把费用分或历史平稳等同保本 |
| 债券/偏债 | 是否有股票/转债、信用、久期和杠杆风险？封闭/持有/滚动期是否适合资金用途？未取得深度字段就缩小相应结论 |
| 主动权益 | 风格、集中度、经理连续性、费用及合同基准是否可解释？不同经理任期和不同区间不能混比 |
| 指数/联接 | 准确标的、覆盖市场、行业结构、实际跟踪质量与费用分别如何？联接和目标ETF的重复收费/豁免需核实 |
| 场内ETF | 除基金净值外，核场内价格/折溢价、成交和交易成本；海外休市、申赎限制可能影响套利，不能见溢价就保证可套利 |
| QDII | 实际地区/行业与汇率暴露、海外日历、净值滞后、限购及到账；QDII不自动等于美股宽基 |

黄金、商品、FOF、养老目标、REITs、海外注册基金等可按合同作公开研究，但当前六类基础模型不适用时保留无分，不套股票指数评分。资料不足不是“风险不存在”。

A/C等份额比较必须按预计持有期、真实销售渠道折扣、销售服务费、赎回阶梯及其他实际费用核对；不使用固定的“A长期、C短期”天数规则。公开表只取得列示费率小计时注明范围，不能拿不完整小计断定总费用最低。基金净值通常已扣运作费，分析历史净收益时不能再重复扣一次。

## 执行方案

给出现在可考虑的动作、证据、前提、加减仓条件与下一次检查触发；没有必要交易时明确建议保持或暂停新增，并解释理由。

比较四种路线：保持现状、暂停重复方向新增、用实际到账新资金纠偏、分批赎回重配。赎回重配需核每笔确认日、可赎/开放窗口、赎回费、预计到账、限购与结算。用户只给金额截图时不虚构可卖份额、成本或持有天数。

定投金额从已确认的可持续投资结余和目标分组出发，现金未到账不提前支用；不默认借钱或动用应急金。暂停/调整条件可以是资金用途改变、实际结余变化、配置偏离或产品实质变化；不能仅因浮亏、排名、均线或基础分机械触发。

允许给出条件性建议，不因不自动下单而拒绝分析。目标差额只是配置算术，交易摩擦、未分类暴露和用户约束仍可能让“立即交易”不合适。

## 本地持仓与记录

`PortfolioManager`维护兼容持仓列表，不是完整交易账本。新增/更新/移除须依据用户已确认事实；“建议卖出”和“用户已卖出”分开。清仓后列表可移除，但原文件自动备份保留。读取损坏文件、并发更新或保存失败会报错，不显示虚假保存成功。未知用null，零份额/零成本保留零；净值须为正数或未知。纠正已记录字段为未知时显式使用`update(..., clear_fields=["cost_nav"])`等字段列表，原记录仍在备份中，不把普通省略参数当作清空。扩展来源字段在更新中保留。

```python
from scripts.portfolio_manager import PortfolioManager
manager = PortfolioManager(portfolio_path="<本地私密路径>/portfolio.json")
# 只在用户确认事实后调用add/update/remove；查看使用list_all/render_table。
```

- 市值快照：代码/份额、币种、市值有效日、金额、来源；单位净值/份额/成本只在确知时记录。研究抓取日不能替代市值记录日。
- 用户确认的交易事实另在本地保留：事件ID、产品代码/份额、渠道、类型、申请/确认日期、金额/份额、费用、分红方式、币种与来源。保留原流水，按事件ID去重；未确认不记成已成交。
- 列表字段不是流水；不自动重建历史成本、现金流、税费、XIRR或历史组合回撤。只有现金流完整且口径核对后才另行计算本人绩效。
- 默认路径的持仓、备份、报告和日志均被忽略；自定义路径要另核隐私与备份位置。不上传个人金额、账户或原流水，不自动同步/创建定时任务。

## 组合核对与持续复盘

使用`portfolio_diagnostics.py`按明确市值与分组核对结构，不从成本推权重，不从基金名称推用途。

```bash
python scripts/portfolio_diagnostics.py --input <本地管理输入JSON> --output <本地私密核对JSON>
```

输入沿用`funds`，增加`holdings_as_of`、`base_currency`及每项`allocation_group`。目标可在`investment_policy.target_allocations_pct`提供，须`targets_confirmed=true`并有`source`。分组仅为用户声明的产品角色，不等于底层穿透；`underlying_id`仅在`underlying_verified=true`时用于同标的提示。

应急/专项条目只有显式`exclude_from_allocation=true`才从配置分母排除。目标差额仅在所有纳入市值已知、日期一致、币种统一、分组完整且目标已确认时输出；不默认未映射分组目标为零。混合币种不直接合计，未知市值不填0。合成输入见[管理示例](../examples/management-input.json)，其中比例不是对真实用户的建议。

在操作报告输入提供`investment_policy`或`management_review=true`会显示“组合管理核对”。这不是交易计划自动生成器。

与用户约定月度或季度核对即可，不要求每天调仓；资金用途/收入变化、经理或合同重大变化、到期开放、显著偏离已确认目标时可提前复核。先考虑新增资金纠偏，再比较交易成本；时间频率、偏离阈值是用户的管理规则，不自动视为已采纳。未经要求不安排通知或定时运行。

一次复盘回答：目标是否改变、现金是否仍够用、结构是否偏离、产品是否仍承担原角色、实际费用与执行是否符合计划、下一次检查何时/因何触发。区分市场结果与决策质量，不因一次涨跌重写整个策略，也不为有报告而强行给交易。

## 交付验收

- 先给用户可行动的结论和条件，再给研究依据；评分和技术指标放辅助位置。
- 所有原条目保留，未知或不适用简要说明；只对影响结论的缺口提问，不堆专业字段空表。
- 个人目标/比例来自用户确认或明确建议情景，不能把合成示例、启发式分数和历史持仓披露写成用户事实。
- 不保证收益、回本时间、最大回撤或某款基金最优。保持具体分析能力，不以通用免责声明代替判断。
